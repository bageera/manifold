# Code Audits — 2026-10-25 (security + ponytail)

Scope: full src/ + crates/ read (~3,300 lines), decode paths traced
record-by-record, panic surface greps, crafted-stream probes, full gate
re-run (fmt/clippy/test/fuzz/CLI roundtrips).

## Security findings

S1 (MEDIUM, verified live) MNF7 decompression bound undercounted mode-3
records: worst record is 833 bytes for a full tile
(1 mode + 256 Y + 2 x 288 chroma-packed), but the limit assumed
776 (1 + 5 + 768 + 2). A legal all-mode-3 file was rejected as a bomb —
verified by crafting one (decode rc=2 "bomb"), then fixed (limit =
tile_count * max(774-record, 833-record) in src/mnf6.rs decode_mnf7),
re-verified (accepted, decodes to exact flat gray). Regression pinned:
tests::mnf7_all_mode3_stream_accepted.

Clean: magic/dims/tile/payload validation order (both decoders + MNF7 +
refdecode); zlib/zstd bomb bounds via take(limit+1) with checked
arithmetic; 4N minimum-stream gate before image allocation; reference
order/shape/transform validation in every mode arm; zstd xxh64
checksum mandatory (zlib Adler32 inherent); trailing-byte rejection;
fuzz 315/315 rejected, 0 panics, 0 wrongful acceptances. DecodeLimits
exposes independent ceilings (pixels/tiles/decompressed/memory);
defaults are the format-derived maxima.

Panic-surface note (info): the only unwrap()/expect()/unreachable!()
outside tests are on slice-to-array conversions that are
bounds-guaranteed, in-memory zlib/zstd writers (infallible), and
transform dispatch guarded by validation that always runs first.
apply_transform asserts t < 8; all callers validate via
transform_is_valid_for / range checks before calling (grepped callers:
codec encode, mnf6 encode + decode, refdecode uses push maps with its
own validated dispatch). Assert stays as defense-in-depth on a research
crate; would become a Result in any hardened production variant.
